### Item 3
**GB 응답 (2026-07-21): ACCEPT (스키마) + 정산 경계 명시 (중요)**

> **스키마 확장 동의**: `source += microgrid_safety`, `target_kw → command` oneOf, `MemberAllocation += setpoint_c` 수용. `DispatchSource` enum 은 Item 1 과 묶어 `{reliability, economic, carbon, optimal, microgrid_safety}` 로 EC 단일 정의.
>
> **⚠ 정산·의무배분 경계 (GB 가 반드시 못박음)**: GB 정산 커널(`dispatch/settlement.py`) + 의무배분(`dispatch/engine.py`) + critics(`dr/critics_integration.py`) + 토론(`dr/debate.py`) 은 **전부 kW 기반**이다 — `obligation_kw = event_target_kw × (baseline_kw / Σbaseline)`. 즉:
> - `command = target_kw` (또는 `peak_limit_kw` 로 환산 가능 시) → GB 정상 정산.
> - `command = setpoint_command`(설정온도 how) → **GB 는 kW 절감 의무를 산출할 수 없어 정산·패널티 계산 불가**. 이 경로는 **GB 우회 = Edge/MGCC 직접 actuation** 트랙으로 간주하고, 사후 `execution_report.reduction_kw`(measured)만 회계에 반영(baseline 대비 실측). 정산 대상이 아니면 `mandatory=false` 명시 필수.
> - 따라서 **oneOf 분기별로 GB 책임을 스키마 `description` 에 명문화** 요청: `target_kw|peak_limit_kw` = GB settlement 대상 / `setpoint_command` = Edge 직접제어(GB 는 measured passthrough).
> - `MemberAllocation.setpoint_c` 는 optional(설정온도 경로일 때만). `allocated_kw` required 는 유지하되, 설정온도 경로에선 `allocated_kw=0` + `setpoint_c` 병기 허용 여부를 EC 에서 결정 필요(현재 `allocated_kw` minimum:0 이라 0 허용됨 → OK).

> **Edge 제안 요지**: `setpoint_command` = `{setpoint_c, ramp, zone?}` — MGCC 가 절감량(what) 대신 설정온도(how) 직접 지정. 단 Edge 는 인터록·critics_gate 통과 후 clamp(그리드 안전 < 사람 안전). 기존 `target_kw` 경로 하위호환 보존.
